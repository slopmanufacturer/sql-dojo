# sql-dojo

Sixty SQL exercises on a seeded SQLite database. You write a query, run
`./dojo.py verify`, and it tells you whether the result matches. No scrolling to
the answers, no guessing whether you got it.

I wrote this because most SQL practice repos are a wall of markdown with the
answer folded away at the bottom. Running a query against real rows is the part
that teaches you something, so every exercise here is executable and graded.

Python 3.8 or newer. No dependencies, no server, no setup.

## Quickstart

```console
$ ./dojo.py list
$ ./dojo.py run 04/03
$ ./dojo.py verify 04/03
```

Write your query in the exercise's `starter.sql`, then run it. Here is a real
session for `04/03` (customers without invoices), starting from an inner join:

```console
$ ./dojo.py run 04/03
  name  country
  ----  -------

0 rows, 2 columns

$ ./dojo.py verify 04/03
FAIL  04/03  customers-without-invoices
expected 6 rows, got 0
  missing: (Anchor Insurance, ES)
  missing: (Blue Harbor, US)
  missing: (Harborline Shipping, BR)
  missing: (Keystone Architecture, GB)
  missing: (Lumen Optics, US)

$ ./dojo.py verify 04/03
PASS  04/03  customers-without-invoices  (6 rows, 2 cols)
```

`./dojo.py hint 04/03` prints the hints, and `--solution` prints the answer if
you would rather compare than struggle.

## What this is not

- Not a course. It assumes you can already write a `SELECT` and takes you to
  window functions by the end.
- Not portable SQL. It is SQLite: `julianday()`, `substr()`, and `||` are fair
  game.
- Not a benchmark. The dataset is small on purpose, so you can eyeball results
  and still see what the query did.

## What's in it

| Chapter | Exercises | Covers |
| --- | --- | --- |
| `01-select-basics` | 6 | projection, aliases, `DISTINCT`, arithmetic, `LIMIT` |
| `02-filtering-sorting` | 8 | `WHERE`, `IN`, `LIKE`, `NULL`, `BETWEEN`, `CASE`, multi-key sorts |
| `03-aggregates` | 8 | `COUNT`, `SUM`, `AVG`, `GROUP BY`, `HAVING`, `COUNT(DISTINCT)` |
| `04-joins` | 10 | inner, left, anti, self, and cross joins, join aggregates |
| `05-subqueries-ctes` | 8 | scalar and correlated subqueries, `EXISTS`, CTEs |
| `06-window-functions` | 8 | `ROW_NUMBER`, `RANK`, `NTILE`, `LAG`/`LEAD`, running totals |
| `07-ddl-modeling` | 6 | `CREATE TABLE`, keys, defaults, `CHECK`, `ALTER`, `UPDATE` |
| `08-analytics` | 6 | churn, MRR, ARPU, funnels, top-N per group, dormancy |

## How grading works

- Your result is compared to `expected.csv`: same number of columns, same rows.
- Column names are not graded, only the count and the values.
- If the reference solution sorts, your rows must be in the same order.
- Numbers compare at six decimal places. `NULL` is not the empty string.
- Every `run` and `verify` starts from a fresh copy of the data, so an `UPDATE`
  or `DELETE` cannot wreck the database.

Exercises are numbered within their chapter: `04/03` and
`04-joins/03-customers-without-invoices` are the same exercise.

## Commands

```console
./dojo.py list [chapter]      show exercises and what you have solved
./dojo.py run <exercise>      run starter.sql and print the result
./dojo.py verify <exercise>   grade starter.sql against expected.csv
./dojo.py hint <exercise>     show hints (add --solution for the answer)
./dojo.py progress            what is left
./dojo.py reset               clear your progress
./dojo.py shell               open a scratch copy in the sqlite3 CLI
./dojo.py build [exercise]    regenerate expected.csv from solution.sql
```

Progress lives in `.dojo/progress.json`, which is gitignored.

## The dataset

A fictional B2B SaaS company, January 2024 through June 2025.

| Table | Rows | What |
| --- | --- | --- |
| `plans` | 5 | plan name, monthly price in cents, seat limit |
| `customers` | 40 | company, country, signup date, plan, churn date |
| `users` | 122 | people at each customer, with a role |
| `invoices` | 277 | monthly invoices with an amount and status |
| `events` | 577 | product events with a timestamp |

`data/seed.sql` is generated by `tools/gen_seed.py` and committed, so the repo
works offline. Running the generator twice produces the same file.

## Editing exercises

Each exercise is a directory:

```
exercises/04-joins/03-customers-without-invoices/
├── prompt.md       the question
├── starter.sql     what you edit
├── hints.md        hints
├── solution.sql    the reference answer
└── expected.csv    generated from solution.sql
```

`./dojo.py build <exercise>` regenerates `expected.csv` from `solution.sql`.
After editing a solution, paste it into `starter.sql` and run `verify` to make
sure the pair still agrees.

## Notes

- On Windows, run `python dojo.py ...` instead of `./dojo.py ...`.
- `./dojo.py shell` needs the `sqlite3` CLI on your `PATH`. Everything else is
  pure Python.
